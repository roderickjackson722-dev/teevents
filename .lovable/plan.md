
# Golf League Management — Phase 1 + 2

Season-long leagues that live alongside tournaments. Managed by existing organizers (org owners/admins). Members are lightweight records identified by a 6-character scoring code — same pattern as tournament players. Payments and the public/member portal come in later phases.

## Scope of this build

**In:** Database schema, "Golf Leagues" section in the organizer sidebar, league list, create/edit league, and a per-league manage view with tabs for **Members, Events, Pairings, Scoring, Settings**.

**Deferred (later phases):** Skins engine, standings/points calculator UI, member-facing dashboard, public `/league/:slug` page, membership + event-fee checkout with 5% platform fee, CSV import/export polish, email automations.

The schema for skins, standings, and point systems is created now so later phases don't require re-migrations.

## Database (one migration)

New tables in `public`, each with `GRANT` + RLS + `updated_at` trigger where applicable:

- `golf_leagues` — league_name, league_slug (unique), organization_id, description, dates, season_year, logo/banner, is_active, is_public
- `league_seasons` — league_id, season_name, dates, is_current
- `league_members` — league_id, member_name, email, phone, handicap_index, membership_status, fee fields, scoring_code (6-char, unique per league, auto-generated by trigger — mirrors `generate_scoring_code`)
- `league_events` — league_id, season_id, event_name, event_date, course_name, course_id, format_type, start_time, registration_deadline, max_players, registration_fee_cents, is_completed
- `league_event_registrations` — event_id, member_id, team_name, pairing_group, pairing_position, tee_time, fee_paid
- `league_event_scores` — event_id, member_id, hole_number, gross_score, net_score, points_earned (unique on event+member+hole)
- `league_standings` — league_id, season_id, member_id, matches_played, points, wins/losses/ties, totals, handicap_diff
- `league_skins` — event_id, hole_number, winner_member_id, skin_amount_cents, is_gross
- `league_point_systems` — league_id, win/tie/loss points, position_points jsonb

**RLS pattern:** organizer read/write via `is_org_member(auth.uid(), organization_id)`; public `SELECT` on `golf_leagues` where `is_public = true` and on child rows via league join. `service_role` full access on all tables.

## Technical notes

- Members are **not** `auth.users`. `league_members.user_id` stays nullable for future account linking; scoring code is the primary identifier for later score-entry flows.
- League slug uniqueness enforced at DB level; slugify from `league_name` client-side, allow manual override.
- Net score computed on write as `gross_score - round(handicap_index * hole_weighting)`. For Phase 2 keep it simple: `net = gross - round(handicap/18)` per hole (documented, easy to swap for full USGA later).
- Standings recomputation is deferred; the table exists but no writer runs yet.
- Skins, member portal, public page, and Stripe checkout are **not** wired — files/routes for those are not created in this phase.
- Types file regenerates after the migration; component code lands after migration approval.
